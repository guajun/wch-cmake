From vendor project to everyday builds

Import once per project. After that, maintain sources and build options in CMake.

01

Generate and build in MRS2

Create the chip project in MounRiver Studio 2 and successfully build its active configuration once. The importer needs the generated makefiles, such as obj/makefile.

Have CMake available on PATH before importing, and Ninja before building. Keep your MRS2 installation for its compiler and tools.

02

Open PowerShell in the project folder

Run the one-line installer above. It downloads the latest release, checks its SHA-256 checksum, and imports the existing MRS2 configuration into this project.

CMakeLists.txtCMakePresets.jsoncmake/scripts/

Append -WithVSCode for optional VS Code tasks. Installation is project-local; the downloaded installer files are cleaned up afterward.

03

Activate the toolchain and build

In the same project folder, replace the example MRS2 path with your installation path, then run:

.\scripts\activate.ps1 -MrsRoot C:\MounRiver\MounRiver_Studio2
cmake --preset release
cmake --build --preset release --parallel

Run the activation command in each new terminal. Importing is a one-time setup; everyday builds use cmake. Add sources in cmake/wch-project.cmake or with target_sources.

Two presets, one environment

release and debug are committed and portable. The activation script exports the machine-local MRS2_ROOT into the current shell, and CMake reads it directly.

Preset Build type Toolchain path Definition
release Release Current shell's MRS2_ROOT Tracked in CMakePresets.json
debug Debug Current shell's MRS2_ROOT Tracked in CMakePresets.json
If MRS2_ROOT is absent, configure stops immediately. The toolchain has no hidden default path and no user preset fallback.

More about the workflow

Installation and verification

The installer generates a standalone CMake project. It does not install a global wch-cmake command. For migration parity checks with the repository scripts, see the README.

Build, flash, debug

wch-cmake handles project generation and parity checks. Use wchlink-cli for probe discovery, flashing, and GDB sessions.
