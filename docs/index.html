One import, one build system

MRS2 remains the device and vendor-code bootstrap. Once imported, the checked-in CMake files own sources, flags, linker behavior, and build composition.

1. Generate

Create the chip project in MRS2 and build its active configuration once.

->

2. Import

Read makefile, subdir recipes, linker script, template, and launch metadata.

->

3. Develop

Add C or C++ files through CMake. MRS2 no longer updates the build graph.

& F:\wch\wch-cmake\wch-cmake.ps1 import -Project F:\wch\blink\CH32X035F8U

Two presets, one environment

release and debug are committed and portable. The activation script exports the machine-local MRS2_ROOT into the current shell, and CMake reads it directly.

Preset Build type Toolchain path Definition
release Release Current shell's MRS2_ROOT Tracked in CMakePresets.json
debug Debug Current shell's MRS2_ROOT Tracked in CMakePresets.json
If MRS2_ROOT is absent, configure stops immediately. The toolchain has no hidden default path and no user preset fallback.

Install and verify

Install the latest release

& ([scriptblock]::Create((irm https://github.com/guajun/wch-cmake/releases/latest/download/install.ps1))) -Project F:\wch\blink\CH32X035F8U

Verify migration parity

& F:\wch\wch-cmake\wch-cmake.ps1 verify -Project .

Release installers

The bootstrap script stages the tagged archive inside the selected project, verifies its checksum, imports CMake and activation files, then removes the staging directory. Nothing is installed globally.

  • PowerShell installer
  • POSIX installer

Responsibility boundary

  • wch-cmake owns project generation and parity checks.
  • wchlink-cli owns probe, flash, and GDB sessions.
