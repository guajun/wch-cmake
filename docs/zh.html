WCH RISC-V · MRS2 → CMake

让 MRS2 工程，
用 CMake 继续开发。

在 MounRiver Studio 2 中完成一次构建，再到工程目录运行一行命令，导入构建配置。接下来，使用 CMake、Ninja 和你喜欢的编辑器继续开发。

安装到当前工程 PowerShell 
& ([scriptblock]::Create((irm https://guajun.github.io/wch-cmake/install.ps1))) -Project .

请在 MRS2 工程根目录运行。-Project . 表示当前目录，无需先克隆仓库。

按三步开始使用 ↓ 查看 GitHub 仓库

从官方工程，到日常构建

每个工程只需导入一次。之后通过 CMake 管理源文件和构建选项。

01

在 MRS2 中生成并构建

在 MounRiver Studio 2 中创建目标芯片工程，并使用当前启用的配置成功构建一次。导入工具需要这次构建生成的 makefile，例如 obj/makefile。

导入前请安装 CMake 并加入 PATH，构建前还需安装 Ninja。保留 MRS2 安装目录，以便使用其中的编译器和工具。

02

在工程目录打开 PowerShell

运行上方的一行安装命令。脚本会下载最新发布版本、校验 SHA-256，并将已有的 MRS2 构建配置导入当前工程。

CMakeLists.txtCMakePresets.jsoncmake/scripts/

如需 VS Code 任务配置，可在命令末尾加上 -WithVSCode。安装仅作用于当前工程，下载的安装临时文件会在结束后清理。

03

激活工具链，开始构建

仍在该工程目录中，将示例中的 MRS2 路径替换为实际安装路径，然后运行：

.\scripts\activate.ps1 -MrsRoot C:\MounRiver\MounRiver_Studio2
cmake --preset release
cmake --build --preset release --parallel

每次打开新终端时，需要重新执行激活命令。导入是一次性准备，日常使用 cmake 构建。新增源文件可修改 cmake/wch-project.cmake，或使用 target_sources。

两套预设，共用环境

release 和 debug 两套预设均纳入版本控制，可跨机器使用。 激活脚本将本机的 MRS2_ROOT 路径导出到当前 shell， CMake 直接读取该环境变量。

预设 构建类型 工具链路径 定义位置
release Release 当前 shell 的 MRS2_ROOT 纳入版本控制的 CMakePresets.json
debug Debug 当前 shell 的 MRS2_ROOT 纳入版本控制的 CMakePresets.json
如果未设置 MRS2_ROOT，配置阶段会立即停止。 工具链不会使用隐藏的默认路径，也不会回退到用户预设。
